# Spec 5f.2 — WC basemaps (NGI + Esri Hillshade Dark)

- **Status:** Approved for planning (2026-04-16).
- **Parent:** extends 5f (BasemapSwitcher, shipped 2026-04-16 commits `1ed45d8` / `5309c9b` / `f6eaf07`).
- **Part of:** Sub-spec A1 of the Cape Farm Mapper port. A2 and A3 follow (see Deferred).
- **Source:** Cape Farm Mapper (CFM) basemap registry, pasted in-session 2026-04-16.

## Problem

Cloudskraal is in the Western Cape. The current BasemapSwitcher offers 7 global basemaps (Esri World Imagery, Hybrid, OSM, Topo, OpenTopoMap, Carto Dark, NASA Blue Marble) — none optimised for South African farming. CFM aggregates NGI's 25 cm WC aerials, topocadastral sheets, and Esri Hillshade — the public-sector SA tiles that beat anything global for operator work. A1 lifts those four sources into CapEx.

## Goal

Add four raster basemaps to the existing `BASEMAPS` registry, with a lightweight type-system upgrade that also sets up A2's Esri MapServer adapter without over-engineering today.

## In scope

- Four new basemap entries (table below).
- `BasemapTileSource.sourceType` discriminator — metadata only, no runtime branching.
- `BasemapDef.coverage` optional field + a coverage pill rendered by BasemapSwitcher.
- TDD: registry validation test + extended BasemapSwitcher tests.
- Manual browser smoke before shipping (per 2026-04-16 handoff discipline).

## Registry shape change

`frontend/src/config/basemaps.ts`:

```ts
export type BasemapSourceType = 'xyz' | 'wmts' | 'imageserver';

export interface BasemapTileSource {
  url: string;                       // fully-baked template with {z}/{x}/{y}
  attribution: string;
  sourceType: BasemapSourceType;     // metadata; no runtime branching in A1
  maxzoom?: number;
  tileSize?: number;
}

export interface BasemapDef {
  id: string;
  label: string;
  description: string;
  primary: BasemapTileSource;
  overlay?: BasemapTileSource;
  thumbBg: string;
  coverage?: 'Global' | 'SA' | 'WC';  // drives UX pill; omit to render nothing
}
```

All seven existing entries get `sourceType: 'xyz'`. No change to `getBasemap`, `loadBasemapPreference`, or `saveBasemapPreference`. `FarmMap.tsx` does not branch on `sourceType` — it continues to pass `bm.primary.url` directly to MapLibre's `tiles` array.

WMTS URLs are pre-baked in the registry using the KVP form:

```
{base}?Service=WMTS&Request=GetTile&Version=1.0.0&Layer={layer}&Style=default&TileMatrixSet=GoogleMapsCompatible&TileMatrix={z}&TileRow={y}&TileCol={x}&Format=image/jpeg
```

with `{z}` / `{y}` / `{x}` left as placeholders for MapLibre to substitute per tile.

## New basemap entries

URLs and attribution strings are live-verified during implementation; any endpoint that fails verification is documented in the handoff and dropped from this spec.

| id | label | description | sourceType | coverage | attribution | candidate host (primary → fallback) |
|---|---|---|---|---|---|---|
| `ngi-aerial-2022` | NGI Aerial 2022 | NGI 25 cm aerial — Western Cape, 2022 | `wmts` | WC | © NGI (DALRRD) | `bp-cdngiapollo.dlrrd.gov.za` → `gis.westerncape.gov.za/hosting` |
| `ngi-aerial-2016` | NGI Aerial 2016 | NGI 50 cm aerial — South Africa, 2016 | `wmts` | SA | © NGI (DALRRD) | `bp-cdngiapollo.dlrrd.gov.za` → `gis.westerncape.gov.za/hosting` |
| `ngi-topo-50k` | Topo 50K | NGI 1:50 000 topocadastral series | `wmts` | SA | © NGI (DALRRD) | `bp-cdngiapollo.dlrrd.gov.za` → `gis.westerncape.gov.za/hosting` |
| `esri-hillshade-dark` | Hillshade | Esri World Hillshade Dark — pure relief | `xyz` | Global | © Esri | `services.arcgisonline.com` |

**Implementer note:** MapLibre substitutes `{z}` / `{y}` / `{x}` placeholders inside query-string values (e.g. `TileMatrix={z}`), so WMTS KVP URLs work directly as `tiles` entries with no helper. Verify during the first basemap add.

Esri Hillshade Dark is an XYZ tile endpoint (`services.arcgisonline.com/.../World_Hillshade_Dark/MapServer/tile/{z}/{y}/{x}`), so it uses the same code path as the existing seven.

## BasemapSwitcher UX

One small change to `BasemapSwitcher.tsx`: when `b.coverage` is set, render a small pill overlaid on the tile thumbnail (bottom-right, `bg-amber-50 text-amber-800 text-[9px]`) displaying the coverage code. Entries without `coverage` render nothing (preserves current look for the existing seven).

Popover grows from 7 to 11 entries; the existing 2-column grid layout stays unchanged. No max-height adjustment needed at 11 entries; if the registry grows past ~14 in A2 follow-ons, revisit.

## Risks

- **NGI WMTS CORS.** `bp-cdngiapollo.dlrrd.gov.za` may block cross-origin requests from `localhost`. Verify immediately after the first entry is added. Fallback: provincial WC Gov mirror at `gis.westerncape.gov.za/hosting` (same data, looser CORS) — switch the URL template if needed.
- **Tile latency.** NGI servers are slower than Esri/OSM CDNs. If tiles take > 5 s at default zoom, set `maxzoom` conservatively (≤ 19) to avoid cascading requests.
- **Dead endpoints.** If live verification shows a URL is dead, drop it from A1 and document in the handoff. A1 ships whichever subset is live.
- **Attribution compliance.** NGI requires visible credit. The attribution string renders in MapLibre's default attribution control (bottom-right, already repositioned per prior commit `d4dcf14` to clear the FAB).
